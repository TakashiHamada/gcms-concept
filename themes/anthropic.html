Overview

概要

GCMS は、属人化しがちな「コンテンツや設定の管理」を、レビュー可能で再現性のあるコードとして表現することを目指します。既存 CMS が抱える運用の重さを、git ベースのワークフローで解消します。

Problem
既存 CMS の複雑さ・属人性
Solution
コードベースで一元管理
Value
再現性・透明性・速度

Principles

設計思想

  1. I.

    Code as Source of Truth

    あらゆる定義をコードで表現し、レビュー・再現可能にします。

  2. II.

    Minimal Runtime

    実行時依存を最小化し、長期に陳腐化しない構成を目指します。

  3. III.

    Composable

    小さな単位で構成し、置換・追加を容易にします。

Architecture

構成

プロジェクトのレイアウトとルート設定の例です。

project layout
gcms/
├─ schema/         # コンテンツのスキーマ定義
├─ content/        # 実体データ (YAML / Markdown / JSON)
├─ pipelines/      # ビルド・変換・検証
├─ adapters/       # 出力先 (Web / API / Static)
└─ gcms.config.ts  # ルート設定
gcms.config.ts
import { defineConfig } from "gcms";

export default defineConfig({
  schema: "./schema",
  content: "./content",
  output: {
    web: { dir: "./dist", baseUrl: "/" },
    api: { dir: "./dist/api" },
  },
  pipelines: ["validate", "transform", "emit"],
});

Workflow

ワークフロー

CLI を使った一般的な操作フローです。

# 1. 初期化
$ npx gcms init my-project

# 2. スキーマ定義
$ gcms schema add Article

# 3. コンテンツ作成
$ gcms content new Article hello-world

# 4. ビルド & プレビュー
$ gcms build && gcms serve
