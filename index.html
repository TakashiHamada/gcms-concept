GCMS.
コードで完結する、軽量コンセプト管理

GCMS は、設定もコンテンツもコードとして扱う、シンプルで再現性の高いシステムコンセプトです。 このページはその設計思想と構成要素をまとめた、生きたドキュメントです。

Concept

設計思想

  1. 01

    Code as Source of Truth

    あらゆる定義・コンテンツはリポジトリ上のコードとして表現し、レビュー可能・再現可能にします。

  2. 02

    Minimal Runtime

    実行時の依存を最小化し、長期にわたって陳腐化しない構成を目指します。

  3. 03

    Composable

    各コンポーネントは小さく、置換・追加が容易な単位に分割します。

Architecture

構成

GCMS の主要コンポーネントと、その間のデータフローをコードで示します。

structure.txt 
gcms/
├─ schema/         # コンテンツのスキーマ定義
├─ content/        # 実体データ（YAML / Markdown / JSON）
├─ pipelines/      # ビルド・変換・検証
├─ adapters/       # 出力先（Web / API / Static）
└─ gcms.config.ts  # ルート設定
gcms.config.ts 
import { defineConfig } from "gcms";

export default defineConfig({
  schema: "./schema",
  content: "./content",
  output: {
    web: { dir: "./dist", baseUrl: "/" },
    api: { dir: "./dist/api" },
  },
  pipelines: ["validate", "transform", "emit"],
});

Workflow

ワークフロー

terminal zsh 
# 1. 初期化
$ npx gcms init my-project

# 2. スキーマ定義
$ gcms schema add Article

# 3. コンテンツ作成
$ gcms content new Article hello-world

# 4. ビルド & プレビュー
$ gcms build && gcms serve
